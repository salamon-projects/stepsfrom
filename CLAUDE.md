# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

StepsFrom lists holiday properties that are **measured** (in PostGIS, against OpenStreetMap data) as truly beachfront. Nothing is hand-reviewed: a property measured in a listed category is on the site automatically; admins can only edit or hide it. (A walking-distance-to-landmarks version with pgRouting and LLM search existed in November 2026 and was removed as too costly to run; migration `20261108120000_remove_walks_and_search` dropped its tables.) README.md is detailed and current; read it for setup, admin workflow, affiliate/price configuration and deployment.

## Commands

```bash
bin/dev                                   # Rails server + Sass watcher, http://localhost:3000 (admin: /admin, admin/admin)
bin/rails db:setup                        # create DBs, load schema, seed (dev seeds include fictional "Demo Bay")
bundle exec rspec                         # all specs (need PostgreSQL + PostGIS)
bundle exec rspec spec/services/waterfront/classifier_spec.rb:42   # single file / example
bin/rubocop                               # rubocop-rails-omakase style
bin/brakeman && bin/bundler-audit         # security checks run in CI
bin/ci                                    # local CI: setup, rubocop, bundler-audit, brakeman (not the specs)
bin/rails osm:import[makarska-riviera]    # import + measure one destination (osm:import_all for all)
bin/rails waterfront:classify[makarska-riviera]   # re-measure without re-importing (no slug = all)
bin/rails websites:check                  # check listed properties' websites now, report broken ones
```

CI runs `bin/rails dartsass:build` before the specs; do the same if a request spec fails on a missing stylesheet. DB connection comes from `DB_HOST`/`DB_PORT`/`DB_USER`/`DB_PASSWORD` or a `postgis://` `DATABASE_URL`. Any PostGIS 3 image works for `db:setup`/`db:schema:load`, but running all migrations from scratch needs pgRouting (`20261103120000_create_walk_network` enables it); production and CI run `pgrouting/pgrouting:16-3.5-3.8.0` (PostGIS plus an unused pgRouting), and changing the image in `config/deploy.yml` needs the Deploy workflow's `db-upgrade` command (`kamal accessory reboot db`). `bin/bundler-audit` in CI uses the latest advisory database, so it can fail on an unchanged commit when a gem (e.g. Rails) gets a security release — update the gem.

Every push to `main` deploys to production (Kamal) once CI passes — a green commit on main is a release.

## Stack constraints

Rails 8.1, Ruby 4.0, HAML views, SCSS via dartsass-rails, Propshaft. Server-rendered only: **no Hotwire, Stimulus or importmap**. JavaScript is limited to small plain scripts in `app/assets/javascripts/` (`map.js` draws Leaflet maps from vendored `vendor/assets/leaflet`; `filters.js`, `stay_fields.js` — range calendar and guest steppers over `shared/_stay_fields` — and the home page's `search_form.js` and `country_tabs.js` are progressive enhancement). Pages must work without JS, and the enhanced fields must submit the same params as the plain ones. Solid Queue / Solid Cache for jobs and cache.

The CSP (`config/initializers/content_security_policy.rb`) allows only same-origin scripts, styles and fonts and no inline `style` attributes: fonts are self-hosted in `app/assets/fonts`, and data-driven positions are drawn as inline SVG attributes (e.g. `shared/_distance_ruler`). Design tokens live in `_variables.scss` (2026-11 redesign: night-sea masthead and panels, Bricolage Grotesque / Inter / JetBrains Mono, coral `$accent` for calls to action and focus, mint/amber/slate for the three listed waterfront categories — keep `map.js` in step). Every page opens on the dark `.masthead` from the layout: put the page title in `content_for :masthead`.

Project principles (from README): no scraping — property/map data only from OSM, prices and links only from official affiliate programmes/APIs. A booking site's "beachfront" label is a hint used to flag conflicts, never to list a property.

## Architecture

**Data flow:** `Destination` (bounding box) → OSM import → geometry tables (`WaterFeature`, `Beach`, `RoadSegment`) + `Property` → measurement → `Verifications::Waterfront` → listed automatically (`Property.published`) → destination page → property page with `Listing`s/prices.

- **OSM import** (`app/services/osm/`): `Osm::DestinationImport` runs one importer per layer (`Importers::Coastline`, `InlandWater`, `Beaches`, `Roads`, `Accommodations`, all `< Importers::Base`) through `OverpassClient` (retries across public Overpass instances; `OVERPASS_URLS` overrides), then re-measures every property. `OsmImportJob` wraps it and records progress/outcome in an `ImportRun` (shown in admin). Re-imports remove map features OSM no longer returns but never delete properties — those get `osm_missing_since` set (scope `missing_from_osm`). Properties an admin edited or hid (`reviewed_at`) keep their name/position/details; others follow OSM.
- **Measurement** (`app/services/waterfront/`): `Measurer` does the PostGIS queries (distance to water, road/promenade crossing, nearest beach, booking-site coordinate mismatch) → `Measurement`; `Classifier` maps it to a category using thresholds in `config/waterfront.yml`; `Classification` orchestrates and saves the result. `ClassifyPropertyJob` runs it after a property moves. If you change thresholds, keep the public "How we verify" page (`app/views/pages/how_we_verify.html.haml`) accurate — it is a ranking-transparency requirement.
- **Verifications** are STI rows in `verifications` (`Verification` base, `Verifications::Waterfront`) holding category, `distance_m` and JSON `evidence` (via `store_accessor`). Properties hold location data plus `hidden_at`/`reviewed_at`. `Property.published`: not hidden, not missing from OSM, inside its destination's area, not of a kind in `Property.excluded_kinds` (`config/listing.yml`, default `camp_site`; still imported, measured and shown in admin; their public pages 301 to the destination; the filter uses `Property.public_kinds`; "How we verify" names them), and a waterfront result in `LISTED_CATEGORIES`. README describes how to add a new verified attribute.
- **Destination areas:** `destinations.area` is the admin's bounding-box rectangle, or a polygon from `config/destination_areas.yml` (Kassandra: the peninsula, since its box also covers Sithonia's west coast; Brač: the island, since its box also covers the mainland Omiš Riviera; set in production by migrations `20261128120000_give_kassandra_its_peninsula_area` and `20261128140000_give_brac_its_island_area`, in seeds for fresh installs). `Property.published` requires `in_destination_area` (`ST_Covers` in plain lon/lat, `Destination.covers_sql`); properties outside stay in admin. `Osm::Importers::Accommodations` queries Overpass by the box but only creates properties inside the area. `Destination` rebuilds `area` from south/west/north/east only when those numbers changed, so saving keeps a polygon — but changing them in admin flattens it to a rectangle (the form warns).
- **Geometry:** SRID 4326 geographic types via `activerecord-postgis-adapter`; build values with the `Geo` helpers (`app/models/geo.rb`, coordinates are `[lon, lat]`).
- **Public search:** `Stay` (ActiveModel: dates + adults/children from params) and `PropertySearch` (filters + ordering; price sort when a valid stay is given, else by waterfront) feed destination pages. `Offer` (a `Data` value) pairs each active `Listing` with a fresh `PriceQuote`, cheapest first, marking the best.
- **Affiliate/prices:** `Affiliate::AutoListings` gives every property automatic listings (`listings.generator`: `stay22` = Stay22 Allez link by name + position when `STAY22_AID` is set; `search` = the site's own search once its `*_TRACKING_URL` is set). Admin-entered listings are never touched; editing an automatic one's URL makes it the admin's, and "Switch off" (active = false) keeps it off. Affiliate env vars reach production as GitHub Actions *variables* via `config/deploy.yml`. Outbound buttons go through `/go/:listing_id` (`OutboundController` logs an `OutboundClick` without IP, `Affiliate::LinkBuilder` applies `config/affiliates.yml` + `*_TRACKING_URL` templates). "Things to do" on destination and guide pages (`shared/_activities`) links to GetYourGuide/Viator searches via `/go/activities/:provider/:destination_id` (`Affiliate::Activities`, `config/activities.yml`; a site appears only when all its env ids are set — `GETYOURGUIDE_PARTNER_ID`, `VIATOR_PID` + `VIATOR_MCID` — otherwise nothing renders and the redirect 404s). Prices come from `Prices::Provider` subclasses in `app/services/prices/providers/` selected by `PRICE_PROVIDERS` (default: `stay22` when the `STAY22_API_KEY` secret is set; `fake` in dev, refuses production). `Prices::Providers::Stay22` searches a destination's area and matches results to properties by distance/name; Stay22's terms cap storage at 60 minutes (55-minute TTL, hourly purge in `config/recurring.yml`). `RefreshPricesJob`/`Prices::Refresher` cache quotes in `price_quotes`; while a job is pending the page reloads once (`prices_loading?`, `?priced=1`).
- **SEO:** country hubs at `/beachfront/:country` (`Country`, a `Data` value built from published destinations' country codes; `CountriesController`) link home → country → destination → property. `SeoHelper` builds schema.org JSON-LD (WebSite on home, BreadcrumbList + ItemList on destinations, Hotel/LodgingBusiness on properties) and the layout adds Open Graph tags with `public/og-image.jpg`. Pages with stay or filter params are `noindex`; others get a canonical URL without a trailing slash (a destination's later pages are indexable, each its own canonical with `?page=N`). Responses are gzipped by `Rack::Deflater` in `config/application.rb` — nothing in front of Puma compresses. `sitemap.xml` lists hubs, then properties best waterfront first, with `lastmod` from `updated_at` (property, verification) — so re-measuring and website checks only touch `updated_at` when something visible changed; `SITEMAP_EXCLUDE_WALKABLE=1` drops "short walk" stays from it. The layout renders Search Console / Bing verification meta tags from `GOOGLE_SITE_VERIFICATION` / `BING_SITE_VERIFICATION` (nothing when unset). Like the affiliate ids, these optional settings are GitHub Actions *variables* passed through `config/deploy.yml`'s `env.clear`.
- **Guides:** `/guides/:slug` pages (`Guide`, a plain object over `config/guides.yml`) rank one destination's top published stays (optionally only some `kinds`, minus an `exclude` list of property slugs; figures count the same set) with copy whose figures are filled from the data (`Guide#facts`). Only shown, linked (destination and country mastheads) and in the sitemap (right after home) while the destination is published and lists something of those kinds.
- **Analytics:** cookieless, first-party, server-side. `PageViewTracking` (an `after_action` in `ApplicationController`, skipped in admin and `OutboundController`) inserts one `PageView` per successful HTML GET of a public page: path without query, referrer host (nil for this site), UTM params (≤100 chars), mobile/desktop, country only from `CF-IPCountry`, and `visitor_hash` (SHA-256 of IP + UA with a salt from `secret_key_base` + UTC date — never store the IP or UA, never add cookies, scripts or GeoIP). Bots (`config/analytics.yml` list, blank UA), DNT/Sec-GPC, prefetches and `?priced=1` reloads are skipped; failures are logged, never raised. `PurgePageViewsJob` deletes rows older than `PAGE_VIEW_RETENTION_DAYS` (default 180). `/admin/analytics` (`Analytics::Report`) reports page views, visitors "unique per day" (the hash rotates daily), referrers, UTM, click-outs by site/property, activity clicks and guide click-through. The privacy page describes all this and shows the retention period — keep it accurate when changing what is recorded.
- **Admin** (`app/controllers/admin/`, layout `admin`) uses a session-based login from `ADMIN_USER`/`ADMIN_PASSWORD`. Recurring production jobs (weekly OSM refresh, weekly website check, quote purge, page view purge) are in `config/recurring.yml`. `CheckWebsitesJob`/`Websites::Checker` hide an "Official website" link that leads nowhere (`website_broken_at`); it only fetches public addresses.

## Tests

RSpec + FactoryBot + Capybara (rack_test) + WebMock (no outbound network). OSM import specs use `FakeOverpassClient` (`spec/support/`) serving `spec/fixtures/files/overpass/sample_bay.json`, grouped by layer — pass it as `client:`. Geometry factories are in `spec/factories/geo_features.rb`; `spec/support/geo_helpers.rb` and `admin_helpers.rb` provide shared helpers; `kassandra_helpers.rb` and `brac_helpers.rb` name points on and off Kassandra's and Brač's polygon areas (for `create(:destination, :kassandra)` / `:brac`).
